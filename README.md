# GridFaultLens

**让 AI 报告的依据可查，让故障分析更准确。**

GridFaultLens 面向电力系统故障录波分析，帮助 AI 根据原始资料和可复算的结果作出判断，并将报告中的数值、图表与相应依据关联起来。工程人员可以从报告回查原文、通道、选窗和计算条件，发现数据误用或解释错误；AI 也能据此继续查证和修正。

项目由本地 Python 工具和 Agent Skill 组成，围绕依据追溯、可靠计算和查证纠错，支持双端故障过程、保护动作与断路器状态分析。

AI-assisted **COMTRADE fault analysis** for power systems, with traceable sources, reproducible calculations, and human review. A Python CLI and agent skill for oscillography and protective-relaying analysis.

## 从报告回到原始依据

多个装置可能使用不同的通道名称、单位、侧别和时间基准。报告中的一个数值即使抄写正确，也可能被用到了错误的对象或阶段；一项计算即使能够复现，也可能不足以支持相应判断。

GridFaultLens 将这些分析条件与报告一同保存。读者可以从正文引用回到原文或计算结果，再查看所用的录波、通道、选窗和样本，判断结论是否得到资料支持。

| 你关心的问题 | 可以查看的依据 |
| --- | --- |
| 报告中的数值从哪里来？ | 保存的原文、原始位置或对应计算结果 |
| 计算用了哪段录波？ | 记录、通道、时间窗口、逐点样本与量值条件 |
| 自动字段摘要有没有遗漏？ | 已接收原文的完整字段与结构文件，以及完整原文 |
| 多组录波如何共同支持结论？ | 两个站端及各自关联的录波、断路器支路和图证 |
| AI 的解释哪里还需要确认？ | 报告中的限制、逐项核查记录与未解决问题 |

AI 提供故障过程解释，工具保存原始资料和计算条件。核查页将两者关联起来，方便你判断：这个数是否来自原文、计算能否复现，以及它是否支持报告中的解释。

## 怎样帮助提高准确性

- **原文有出处。** 报告数值与原文位置或计算结果绑定，减少无依据数值和转述中的遗漏。
- **计算有条件。** 工具按选定通道和窗口计算，保留单位、侧别、样本及适用限制，便于核对是否用对数据。
- **疑点能回查。** 完整原文、字段结构和波形为 AI 查证纠错提供材料，人工也能检查其解释和修订依据。

这些机制分别帮助减少无据陈述、计算错误和数据误用。字段含义、事件关系及工程结论仍包含模型判断，原文与计算条件的保留使这些判断有据可核。

## 快速开始

### 安装

需要 **Python 3.11 或更高版本**。安装过程会获取 Pillow、python-docx 等依赖。中文绘图需要系统安装宋体或 Noto Sans CJK 字体；仓库不分发字体。

```sh
git clone https://github.com/BigDemoBear/gridfault-lens.git
cd gridfault-lens
python -m pip install .
```

项目名称为 **GridFaultLens**，命令为 `powerfault`，也可以通过 `python -m powerfault` 调用。

## 分析自己的资料

GridFaultLens 与能够读取文件、运行本地命令和查看图片的 AI 智能体配合使用。模型服务由你选择的平台提供，工具安装在本地。

仓库中的 `skills/fault-line-report` 提供分析指引，可添加到平台支持的 Skill 目录；也适用于能够直接读取项目指引的平台。接入方式见 [Skill 使用说明](skills/fault-line-report/README.md)。

开始分析时，你需要提供：

| 内容 | 用途 |
| --- | --- |
| 录波目录 | 包含配套 CFG/DAT 及已有的装置 HDR、INF、XML |
| 分析目标 | 例如故障发展过程、保护动作、断路器分合或重合闸结果 |
| 输出位置 | 保存报告、图表及证据包 |
| 补充说明（可选） | 运行方式、接线、通道含义或时间基准，帮助解释歧义 |

报告按线路两个站端组织，每端可以关联多组录波和多个断路器。只有一端资料时，可在现有证据范围内形成报告，并说明另一端的资料缺口。

### 自动摘要之外，原文仍然可查

证据包除自动字段摘要外，还包含完整原文及 `source-structure.json` 字段结构文件。已接收文本的全部原文行，以及合法 XML 中的标签、属性和层级关系，都可以在其中查看；没有进入自动摘要的字段也会保留。

AI 可以结合这些上下文解释单位、阶段、一次或二次侧别和时间基准；你也可以回到相同位置复核。字段结构文件提供浏览入口，字段的电气含义仍由分析与复核确定。它只覆盖工具已接收的资料，支持格式见下方说明。

## 你会得到什么

分析完成后，你会得到一份带图表和来源引用的故障分析报告，以及配套的 `data/` 证据目录。报告便于阅读结论，证据目录便于逐项检查依据：

| 产物 | 用途 |
| --- | --- |
| 故障分析报告 | 了解故障过程、保护与断路器动作、波形解释及未确认事项 |
| 引用核查页 | 点击正文数值，查看对应原文、原始位置或具体计算 |
| 原件、原文快照与字段结构 | 对照原始资料，查看字段的上下文及自动摘要之外的信息 |
| 图表、样本与计算记录 | 检查通道、选窗、单位，以及计算使用的实际数据 |
| 报告源稿与逐项核查记录 | 对照 AI 的判断依据，找到资料缺口、证据冲突和人工复核重点 |

报告中的数值引用可以打开核查页，再查看原文与计算条件。报告、图表和证据使用本地链接，整体保存或转交交付目录即可保留这些对应关系。

这些材料帮助你检查 AI 的工作依据；电气判断是否成立，仍由人工结合资料复核。

## 能力与适用范围

| 范围 | 当前能力 |
| --- | --- |
| 录波读取 | COMTRADE CFG/DAT；ASCII、BINARY、BINARY32、FLOAT32 |
| 补充原文 | HDR、INF、XML；保存原文及完整字段结构，提供可追查引用 |
| 资料组织 | 围绕线路两个站端组织，每端可关联多组录波、多个断路器及相应证据 |
| 计算绘图 | 模拟量波形、开关量变位、选窗基波量值和本端相量关系 |
| 报告交付 | Markdown 报告、引用核查页、证据包和人工核查记录；另保留表单与 Word 接口 |
| 补充证据 | 图片、附加图表及补充计算记录可随报告一同保存 |

默认分析范围包括故障相别、接地特征、电压电流、直接记录的零序量、装置明确记载的最大量与测距、保护动作、断路器分合、故障切除、重合、恢复状态和本端相量关系。也可根据你的分析目标选择其中一部分。

报告会区分已确认结果、资料不足和证据冲突。采样覆盖、通道含义、极性、侧别和时基都会影响判断范围；跨端同步和相角关系还取决于相应资料是否齐全。原始采样缺口会保留在证据中。

现场物理诱因和录波结束后的状态，通常还需要现场资料支持。本项目提供分析辅助与核查手段，不作通用准确率承诺，也不替代运行、调度或保护决策。

## 数据与隐私

仓库不附带录波数据、现场报告、模型工作记录或开发实验结果。代码不内置模型 API、上传入口或遥测；调用平台是否向远程服务传输资料，取决于平台与用户配置。

生成的证据包会保留输入原件、文件名、站线名称、通道、时间、参数和附件，**不会自动脱敏**。完整字段结构也可能包含这些信息。真实资料的处理和对外提供需分别确认权限，详见 [数据安全说明](SECURITY.md)。

COMTRADE 是国际通用的暂态数据交换格式。厂商 HDR/XML 扩展及其具体字段不必然属于该标准；公开的格式规范也不意味着实际运行数据可以公开。
