# 故障线路报告

你负责理解原文、选择工具、解释电气过程、看实际成品并纠错。工具未取得不等于原文没有。事实只取原生CFG/DAT及装置HDR/INF/XML，不把目录标签、既有报告或示例当答案。

## 取证与工具

用extract保留材料，读materials.json及相关冻结原文；source-structure.json另列已接收原文的完整字段与结构，可按需查看未被自动字段覆盖的内容。确认站端、线路、通道、阶段、单位、侧别和时基，再选窗口。保留两个站端，每端可有多组录波和多个断路器；不凭时刻相近就自动跨端对时。

用analyze独立计算绘图，输入见[工具输入](references/plan.md)。先用现有能力；不足时再用脚本或[限时补充方法](references/supplementary-method.md)，记录输入、方法、输出与限制。普通支路图及已有结果直接用--analysis或--attach纳入，不登记新方法。

语义读取从初稿前开展，见[原文与解释](references/semantic-reading.md)。按需查[判据参考](references/判据参考.md)：故障类型第2节、量值第3节、相量方向第4节、动作切除第5节、重合第6节、测距恢复第7节。证据不支持的量和结论如实留缺。

## 成稿与自主纠错

自己编写report-source.md，按故障信息、录波图解析、综合总结组织。数值用原生或计算引用；由你写缺项、原文核查状态、单位解释和依据。compose展开报告和核查页。只改文字复用图证；补算纳入新结果。

查看实际报告和图，默认两轮自查：先找问题并处理，再回看修订。发现不符预期就主动查原文、换窗、补算或改稿，不等主代理提示。没有候选数或轮数硬上限；不重复无新证据的操作，遵守用户预算和资料边界。

核对原生/计算含义、对象、阶段、单位、侧别、时间、采样覆盖、相角条件和来源。接点名称、保护出口、位置变位、实际停流不能混称同一事件；未知原因、最大量、方向及未覆盖时段不能靠默认值补齐。

## 一次交付

最后按[审查与交付](references/writing.md)交代默认15类所选变量及具体限制，登记已审核内容的成文决定。deliver DRAFT review.json --output DELIVERY完整核对一次并打包。出错按具体原因自主修正后重检。

交付一份报告或障碍说明和data，保留原件、原文位置、数值条件、图、样本CSV、模型源稿和人工核查记录，使人能识别AI有据的工作、误解和未验证项。程序核对成功不证明电气推理正确。
